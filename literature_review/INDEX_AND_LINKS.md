Literature Review:

Papers are grouped by **area of study**. Each paper keeps its original number — the
numbers are stable identifiers referenced from `THESIS_RELEVANCE.md` and
`IMPLEMENTATION_LITERATURE_MAPPING.md`, so they are intentionally non-sequential within a
section.

**Primary reference (foundational — the methodology this project replicates and extends):**
- **C0.** [Can Security Rules Make AI Generated Code Safer? (Project CodeGuard validation)](https://community.cisco.com/t5/security-blogs/can-security-rules-make-ai-generated-code-safer/ba-p/5353605) ([Local copy](cisco_codeguard_validation_blog.md))
    * **Description:** Cisco Security Blog (Thomas Bartlett, 2025-12-09; grey literature — no peer-reviewed paper). Baseline vs. CodeGuard-rules agent (GPT-5) across 2,717 prompts / 5,434 generations; Semgrep `p/security-audit` counting ERROR+WARNING; findings 415→264 (−36.4%, p<0.05). Source of the thesis's Semgrep setup, datasets (CyberSecEval, SecurityEval), baseline-vs-rules design, and CodeGuard rules as system-under-test. The thesis **extends** it by searching for semantics-preserving rule-set repairs that reduce vulnerable generation further; adversarial maximisation is secondary.

## Area 1 — Metamorphic Testing: MR catalogs, frameworks & applications

- **1.** [Metamorphic Testing of Large Language Models for Natural Language Processing](https://arxiv.org/abs/2511.02108v1)
    * **Description:** Catalogs 191 Metamorphic Relations (MRs) for NLP tasks to automate prompt mutation and validation without human-labeled data. It highlights the use of semantic similarity checks to expose LLM faults while revealing the inherent challenges and high false-positive rates of semantic equivalence in free-form natural language.
- **2.** [LLMORPH: Automated Metamorphic Testing of Large Language Models](https://valerio-terragni.github.io/assets/pdf/cho-ase-2025.pdf)
    * **Description:** Introduces the LLMORPH tool, which practically implements a subset of 36 MRs to automate metamorphic testing. It utilizes both programmatic functions and LLM-based few-shot prompting to transform inputs and uncover faulty behaviors in LLM-based NLP systems.
- **8.** [Validating LLM-Generated Programs with Metamorphic Prompt Testing](https://arxiv.org/abs/2406.06864)
    * **Description:** Introduces a Metamorphic Prompt Testing approach to validate LLM-generated code without relying on ground-truth test oracles. It utilizes LLM-based paraphrasing to create multiple prompt variants and applies coverage-guided fuzzing to cross-validate the resulting programs' outputs via a majority-consensus algorithm.
- **9.** [METAL: Metamorphic Testing Framework for Analyzing Large-Language Model Qualities](https://arxiv.org/abs/2312.06056)
    * **Description:** Introduces the METAL framework, which utilizes Metamorphic Testing to systematically mutate LLM inputs via 13 character-, word-, and sentence-level perturbations. It proposes using Semantic Textual Similarity (STS) metrics to automatically validate intent preservation and calculate perturbation quality, moving beyond standard Attack Success Rate (ASR) evaluations.
- **12.** [Validating LLM-Generated SQL Queries through Metamorphic Prompting](https://matafeiyanll.github.io/paper/FSE26-MRSQLGen.pdf)
    * **Description:** Details four discrete prompt mutation strategies—Intent Perturbation, Logical Decomposition, Constraint Explicitization, and Error-Type Reflection—used to systematically transform instructions. To ensure these mutations preserve the core intent without requiring ground-truth labels, it evaluates the downstream SQL execution results using relational operators like equivalence, subset, and superset.
- **16.** [Detecting and Reducing the Factual Hallucinations of Large Language Models with Metamorphic Testing](https://dl.acm.org/doi/10.1145/3715784)
    * **Description:** Proposes DrHall, which leverages 6 base MRs (split into Questioning MRs that transform the question, and Answering MRs that probe the original answer) to detect and correct factual hallucinations in black-box LLMs. The approach exploits the instability of hallucinated answers — hallucinating models produce inconsistent responses under MT — achieving F1 > 0.856 for detection and > 53% correction rate via multi-path voting. The method requires no external knowledge base or model confidence scores.
- **23.** [Metamorphic Testing for Web System Security (MST-wi)](https://arxiv.org/abs/2208.09505) ([PDF](https://orbilu.uni.lu/bitstream/10993/54576/1/Nanazin_SecurityMetamorphicTesting_Journal.pdf))
    * **Description:** Constructs 76 system-agnostic Metamorphic Relations for web security testing, organized into 10 structural patterns (P1-P10) mapped against MITRE CWE principles. Uses relational oracles (equality, subset, superset) to verify input-output consistency without ground-truth labels. Covers 39% of OWASP testing activities not automated by existing techniques, detecting 102 different vulnerability types across 45% of CWE categories.
- **25.** [zkCraft: Prompt-Guided LLM as a Zero-Shot Mutation Pattern Oracle for TCCT-Powered ZK Fuzzing](https://arxiv.org/abs/2602.00667) ([HTML](https://arxiv.org/html/2602.00667v3))
    * **Description:** Employs an LLM as a zero-shot mutation pattern oracle for fuzzing zero-knowledge circuits. Features a dual-oracle architecture: the Mutation-Oracle generates edge-case expressions from constraint statements, and the Pattern-Oracle takes verified counterexamples and synthesizes targeted mutation directives plus sampling code. Achieves 88 true positives with 0 false positives across 452 real-world Circom circuits, outperforming all existing tools while maintaining constant proof overhead.

## Area 2 — LLM robustness, instruction-following & prompt sensitivity

- **4.** [Say It Another Way: Auditing LLMs with a User-Grounded Automated Paraphrasing Framework](https://arxiv.org/abs/2505.03563)
    * **Description:** Introduces the AUGMENT framework to replace unconstrained prompt paraphrasing with structured, user-grounded linguistic mutations such as formal style, dialect, and active/passive voice. It utilizes a multi-dimensional quality control filter that evaluates instruction adherence, semantic similarity, and realism (perplexity ratio) to ensure strict intent preservation.
- **5.** [Do LLMs "know" internally when they follow instructions?](https://arxiv.org/abs/2410.14516)
    * **Description:** Uses linear probing to identify an internal "instruction-following dimension" within LLM input embeddings, proving that models often map success or failure at the very first token. It demonstrates via sensitivity analysis that this internal dimension is heavily influenced by prompt phrasing rather than task difficulty, validating semantic rephrasing as a potent mutation operator.
- **6.** [Same Question, Different Words: A Latent Adversarial Framework for Prompt Robustness](https://aclanthology.org/2025.emnlp-main.1595.pdf)
    * **Description:** Presents Latent Adversarial Paraphrasing (LAP), a framework that operates in the continuous latent space of the LLM by injecting trainable perturbations into hidden states or embeddings. It demonstrates that the distance in embedding space between original and perturbed prompts is highly predictive of worst-case failures, using an $L_2$-norm constraint to mathematically guarantee semantic preservation.
- **7.** [Towards LLMs Robustness to Changes in Prompt Format Styles](https://arxiv.org/abs/2504.06969)
    * **Description:** Introduces the Mixture of Formats (MOF) technique to mitigate style-induced prompt brittleness by diversifying the formatting styles of few-shot examples within a single prompt. It relies on non-semantic structural mutations (e.g., altering punctuation, capitalization, and delimiters) to demonstrate that exposing models to varied formats significantly reduces performance spread and improves both the minimum and maximum accuracy
- **10.** [Does Tone Change the Answer? Evaluating Prompt Politeness Effects on Modern LLMs: GPT, Gemini, LLaMA](https://arxiv.org/abs/2512.12812v1)
    * **Description:** Investigates the impact of pragmatic prompt mutations (e.g., injecting "Very Friendly" or "Very Rude" prefixes) on LLM accuracy across various domains. It demonstrates that while rigid STEM tasks remain largely robust to tone changes, subjective Humanities tasks exhibit measurable tone sensitivity depending on the specific LLM being tested.
- **13.** [Persistent Instability in LLM's Personality Measurements: Effects of Scale, Reasoning, and Conversation History](https://arxiv.org/abs/2508.04826v3)
    * **Description:** Investigates the behavioral instability of LLMs by systematically mutating prompts across specific axes: semantic paraphrasing, persona injection, reasoning (Chain-of-Thought) toggling, and conversation history inclusion. By evaluating the Standard Deviation of model responses across hundreds of runs , the study demonstrates that minor prompt variations trigger severe behavioral shifts, and counter-intuitively, that enforcing step-by-step reasoning actually amplifies output variability. For prompt optimization frameworks, it highlights the necessity of using multi-run variance as a core metric to ensure a mutated instruction reliably preserves its intended outcome. 
- **15.** [Prompt Repetition Improves Non-Reasoning LLMs](https://arxiv.org/abs/2512.14982v1)
    * **Description:** Demonstrates that repeating the input prompt twice improves LLM accuracy on 47 of 70 benchmark-model combinations with 0 losses, with no latency or output length increase. The effect arises from the causal attention mechanism: the second copy allows all prompt tokens to attend to the full prompt context, addressing an architectural limitation of unidirectional attention. The technique is most effective for non-reasoning models and represents a minimal, drop-in robustness improvement.

## Area 3 — Search-Based Software Testing & prompt/agent optimization

- **3.** [Search-based Selection of Metamorphic Relations for Optimized Robustness Testing of Large Language Models](https://arxiv.org/abs/2507.05565)
    * **Description:** Applies Search-Based Software Testing (SBST) algorithms to optimize the selection and combinatorial chaining of Metamorphic Relations, addressing the infinite search space and high token costs of LLM testing. It identifies specific "silver bullet" perturbations — in particular `SynonymReplacement()` and `AddRandomWord()` — and the MOEA/D multi-objective genetic algorithm as the best-performing approach for balancing failure rate against token cost.
- **11.** [STELLAR: A Search-Based Testing Framework for Large Language Model Applications](https://arxiv.org/abs/2601.00497)
    * **Description:** Introduces a feature discretization methodology to navigate the continuous natural language input space by breaking prompts down into parameterized, finite dimensions (content, stylistic, and perturbation features). It frames prompt mutation as a discrete combinatorial search problem using rigid templates, effectively preserving the core semantic intent by construction rather than relying on complex post-hoc semantic validation.
- **17.** [Survival of the Safest: Towards Secure Prompt Optimization through Interleaved Multi-Objective Evolution](https://arxiv.org/abs/2410.09652) ([PDF](https://aclanthology.org/2024.emnlp-industry.76.pdf))
    * **Description:** Introduces an interleaved multi-objective evolution framework (SoS) for prompt optimization that simultaneously optimizes task performance (KPI) and safety/security. Uses three mutation operators — semantic mutation (controlled lexical variation), feedback mutation (domain-specific agents critique and improve), and crossover (blending traits from two parent prompts) — with Pareto-optimal selection requiring improvements above a convergence threshold δf. Outperforms single-objective methods (APE, PromptBreeder, PhaseEvo, InstructZero) by preventing the sacrifice of security for performance.
- **18.** [Evolving Excellence: Automated Optimization of LLM-based Agents (Artemis)](https://arxiv.org/abs/2512.09108) ([PDF](https://arxiv.org/pdf/2512.09108))
    * **Description:** Presents ARTEMIS, a no-code evolutionary optimization platform that jointly optimizes LLM agent configurations (prompts, tool descriptions, model assignments, continuous parameters) through semantically-aware genetic operators powered by LLM ensembles. Uses hierarchical evaluation — cheap LLM-based filters before expensive benchmark validation — to minimize computational cost. Achieves 13.6% acceptance rate improvement (competitive programming), 10.1% performance gain (code optimization), 36.9% token reduction (reasoning), and 22% accuracy improvement (mathematics).
- **19.** [SPRIG: Improving Large Language Model Performance by System Prompt Optimization](https://arxiv.org/abs/2410.14826) ([HTML](https://arxiv.org/html/2410.14826v2))
    * **Description:** Introduces an edit-based genetic algorithm for optimizing system prompts — the general instructions that guide LLM behavior across tasks. Uses a seed corpus of 300 components across 9 categories (CoT, roles, styles, emotions, scenarios, safety, etc.) with four mutation operations (add, rephrase, swap, delete) and UCB-based pruning for component selection. A single optimized system prompt matches task-specific optimization across 47 task types, generalizing across model families, parameter sizes, and languages.
- **21.** [Search-based Software Testing Driven by Automatically Generated and Manually Defined Fitness Functions (ATheNA)](https://arxiv.org/abs/2207.11016) ([Survey](https://arxiv.org/abs/2512.10079))
    * **Description:** Proposes the ATheNA framework combining automatically generated fitness functions (derived from formal requirements) with manually defined domain-knowledge fitness functions into a hybrid composite. Engineers embed expertise about conditions likely to trigger failures, and the composite fitness guides SBST search more effectively than either component alone. Validated on automotive and medical case studies from the ARCH competition, generating more failure-revealing test cases than baseline tools.

## Area 4 — Multi-objective & expensive optimization (algorithmic precedents)

*Papers 41–43 are the direct algorithmic precedents for the (1+1) EA + Pareto archive and for expensive-fitness many-objective optimization (41 and 42 supervisor-provided; 43 the closest combined precedent).*

- **26.** [The Weights can be Harmful: Pareto Search versus Weighted Search in Multi-Objective Search-Based Software Engineering](https://arxiv.org/abs/2202.03728)
    * **Description:** Across 38 systems from 3 SBSE problems (604 comparisons), shows Pareto search significantly outperforms weighted-sum search in up to 77% of cases given a sufficient search budget. Empirical justification for dropping weighted composite fitness in favor of **Pareto-dominance archive admission** (which Chen & Li directly advocate; note: they also find weighted search more budget-efficient). **Authors:** Tao Chen & Miqing Li, ACM TOSEM 2022.
- **27.** [A Fast and Elitist Multiobjective Genetic Algorithm: NSGA-II](https://ieeexplore.ieee.org/document/996017)
    * **Description:** Canonical multi-objective evolutionary algorithm providing formal definitions of non-dominated sorting, crowding distance, and Pareto front maintenance. Referenced as foundational baseline for multi-objective alternatives. **Authors:** Kalyanmoy Deb et al., IEEE Transactions on Evolutionary Computation, 2002.
- **28.** [Nonlinear Multiobjective Optimization](https://scholar.google.com/scholar?q=Miettinen+Nonlinear+Multiobjective+Optimization)
    * **Description:** Standard MOO-theory textbook. Cited for the **formal Pareto-optimality definition** (Def 2.2.1, §2.2) behind the archive's dominance rule; lexicographic ordering (Ch 4 §4.2) is a considered-but-rejected a-priori alternative. **Author:** Kaisa Miettinen, Kluwer Academic Publishers, 1999.
- **41.** [Automated Repair of Feature Interaction Failures in Automated Driving Systems (ARIEL)](https://dl.acm.org/doi/10.1145/3395363.3397386)
    * **Description:** Introduces ARIEL, a (1+1) Evolutionary Algorithm + many-objective archive method for automatically repairing faulty integration rules in automated driving systems. Each objective corresponds to one safety requirement; the archive stores Pareto-optimal partial patches and is bounded at 2×k entries (k = number of requirements), with overflow eviction by the aggregated fitness D = Σ Ω_i. Uses a stagnation-restart counter h (their empirical choice: h=8) and Roulette-Wheel mutator selection weighted by fault-localization suspiciousness. Single-state (1+1) was chosen specifically because their test cases are simulation-based and expensive (minutes each), making population-based GP infeasible. Outperforms GP and Random Search baselines on two industrial ADS systems within a 16h wall-time budget.
- **42.** [A Survey on Handling Computationally Expensive Multiobjective Optimization Problems with Evolutionary Algorithms (Chugh et al., Soft Computing 2019)](https://www.researchgate.net/publication/321723936_A_survey_on_handling_computationally_expensive_multiobjective_optimization_problems_with_evolutionary_algorithms)
    * **Description:** Comprehensive survey of 45 algorithms (2008–2016) addressing the high evaluation cost of multiobjective EAs. Establishes the taxonomy of problem / function / fitness approximation, formal definitions of Pareto optimality, ideal/nadir vectors, evolution control (fixed vs adaptive), and the function-approximation framework with two stages (initial sampling and surrogate-managed evolution). Catalogs the major Kriging-based algorithms (ParEGO, SMS-EGO, MOEA/D-EGO, K-RVEA) and non-Kriging variants (RBF, neural networks, SVR). Documents fitness-approximation alternatives that predict rank, hypervolume contribution, or dominance class rather than the objective values themselves (Pareto-SVM, ASM-MOMA). Function-evaluation budgets across surveyed algorithms range 50–30,000, placing our 5000-Semgrep-call budget in the upper-expensive band.
- **43.** [Metamorphic-Based Many-Objective Distillation of LLMs for Code-Related Tasks](https://dl.acm.org/doi/abs/10.1109/ICSE55347.2025.00230)
    * **Description:** Casts robust knowledge distillation of code LLMs as a many-objective optimization: it compresses a teacher (CodeBERT / GraphCodeBERT) into a ~3 MB student that is robust to metamorphic code changes. Four objectives — model size, **prediction flips** (robustness: inputs where the student's prediction differs between a snippet and its semantics-preserving variant), FLOPs, and accuracy/F1 — are solved with **AGE-MOEA** (Latin Hypercube initialization, SBX crossover + polynomial mutation + a repair operator) and two **Gradient-Boosting surrogate models** that predict accuracy and prediction-flips without retraining each configuration. Metamorphic variants come from natural, semantics-preserving renaming of functions/parameters (tree-sitter-validated). Versus AVATAR: 47% more robust, 25% more efficient, comparable-or-higher accuracy at 3 MB; AGE-MOEA beats NSGA-II/III and MOEA/D on hypervolume. The **closest published precedent** for this thesis — metamorphic testing + many-objective optimization — from the same author lineage as ARIEL (TU Delft). The thesis differs in its target (natural-language security rules rather than code/model configurations) and uses output divergence only as a diagnostic while its primary direction searches for safer generated code. **Author:** Annibale Panichella, ICSE 2025.

## Area 5 — Adaptive operator selection / multi-armed bandits (future ablation)

*The bandit strategies below were prototyped earlier and replaced by the EA + Pareto archive with uniform mutator selection. They are retained only as the citation set for a possible future bandit-vs-EA ablation (mutator selection is currently uniform).*

- **34.** [Finite-time Analysis of the Multiarmed Bandit Problem (UCB1)](https://www.researchgate.net/publication/220343796_Finite-time_Analysis_of_the_Multiarmed_Bandit_Problem)
    * **Description:** Foundational UCB1 paper establishing O(log T) regret with exploration bonus `c · √(ln t / n_i)` where `c = √2`. Canonical bandit baseline for adaptive mutator selection. **Authors:** Auer, Cesa-Bianchi, Fischer, 2002.
- **35.** [On Upper-Confidence Bound Policies for Switching Bandit Problems](https://www.researchgate.net/publication/221393905_On_Upper-Confidence_Bound_Policies_for_Switching_Bandit_Problems)
    * **Description:** Introduces D-UCB (discount-based) and SW-UCB (sliding-window) for non-stationary bandits. D-UCB applies γ-discount to historical observations, giving exponentially higher weight to recent pulls — appropriate for a reward distribution that drifts as mutations compound. **Authors:** Garivier & Moulines, ALT 2011.
- **36.** [Adaptive Operator Selection Based on Dynamic Thompson Sampling for MOEA/D](https://arxiv.org/abs/2004.10874)
    * **Description:** Decays Beta posterior parameters by γ at each pull with only one hyperparameter vs. D-UCB's three. Thompson sampling empirically outperforms UCB-family in sparse Bernoulli-like regimes — matching the generation-inert mutator pattern (most mutators inert, occasional wins). **Authors:** Lei Sun & Ke Li, 2020.
- **39.** [An empirical evaluation of thompson sampling](https://dl.acm.org/doi/10.5555/2986459.2986710)
    * **Description:** Shows Thompson sampling is competitive and in some cases significantly outperforms UCB on sparse-reward tasks. Supports a Thompson-style strategy (DYTS) over UCB-family — relevant only to a possible future bandit-vs-EA ablation (mutator selection is currently uniform). **Authors:** Chapelle & Li, NeurIPS 2011.

## Area 6 — Embedding & code-similarity metrics (validation & fitness)

- **22.** [CodeScore: Evaluating Code Generation by Learning Code Execution](https://arxiv.org/abs/2301.09043) ([OpenReview](https://openreview.net/pdf/e6e11b18ee748e3bdbad68e8b1a200fa1721c8ca.pdf))
    * **Description:** Introduces CodeScore, built on the UniCE framework, which fine-tunes models to predict execution-based outcomes (PassRatio and Executability) without actual dynamic execution. Supports three input modalities: reference-code-only, natural-language-only, and combined. Achieves up to 58.87% correlation improvement with functional correctness compared to match-based metrics like BLEU and CodeBLEU, addressing the fundamental disconnect between textual similarity and functional equivalence in code evaluation.
- **29.** [CodeBLEU: a Method for Automatic Evaluation of Code Synthesis](https://arxiv.org/abs/2009.10297)
    * **Description:** Extends BLEU with syntactic AST matching and data-flow graph matching for code evaluation. Four-component metric (n-gram BLEU + keyword-BLEU + AST + data-flow) captures structural code differences. Primary code-divergence metric for the thesis. **Authors:** Ren et al., 2020.
- **30.** [Revisiting Code Similarity Evaluation with Abstract Syntax Tree Edit Distance](https://arxiv.org/html/2404.08817v1)
    * **Description:** AST edit distance via tree-sitter + APTED. Alternative code-similarity metric using structural editing distance. Rejected in favor of CodeBLEU due to limited language support and modest execution-match correlation. **Authors:** Song et al., ACL 2024.
- **31.** [MTEB: Massive Text Embedding Benchmark](https://arxiv.org/abs/2210.07316)
    * **Description:** Evaluates 33 embedding models across 58 datasets and 8 task types; finds no model dominates all tasks. The `all-mpnet-base-v2` STS ranking the thesis relies on is from the MTEB leaderboard, not the paper text. **Authors:** Muennighoff et al., EACL 2023.
- **32.** [Sentence-BERT: Sentence Embeddings using Siamese BERT-Networks](https://arxiv.org/abs/1908.10084)
    * **Description:** Foundational architecture for sentence-level embedding approach used throughout the pipeline. Siamese BERT-network framework enabling efficient semantic similarity computation. Every SBERT call implements this architecture. **Authors:** Nils Reimers & Iryna Gurevych, EMNLP 2019.
- **33.** [SecureBERT 2.0: Advanced Language Model for Cybersecurity Intelligence](https://arxiv.org/abs/2510.00240)
    * **Description:** ModernBERT-based domain-specific embedding model (cybersecurity corpus). Possible future drop-in alternative to `all-mpnet-base-v2`; not currently used. **Authors:** Aghaei et al., Cisco AI, 2025.

## Area 7 — Security evaluation: SAST tools & benchmarks

- **14.** [Cybersecurity AI Benchmark (CAIBench): A Meta-Benchmark for Evaluating Cybersecurity AI Agents](https://arxiv.org/abs/2510.24317v1)
    * **Description:** Introduces a comprehensive, multi-domain framework that evaluates LLM agents across both offensive and defensive tasks, integrating Jeopardy CTFs, Cyber Ranges, and privacy assessments. It empirically demonstrates a profound "capability gap" where frontier models excel at theoretical cybersecurity knowledge but consistently fail at practical, multi-step execution and cyber-physical target exploitation.
- **20.** [SCAFFOLD-CEGIS: Preventing Latent Security Degradation in LLM-Driven Iterative Code Refinement](https://arxiv.org/abs/2603.08520) ([HTML](https://arxiv.org/html/2603.08520v1))
    * **Description:** Reveals the "iterative refinement paradox": optimizing LLM code output against SAST tools (like Semgrep) actually increases latent security degradation from 12.5% to 20.8%, as models learn to structurally evade rules rather than enforce them. Proposes a four-layer gated verification framework with semantic anchoring (function-level, data-flow-level, pattern-level) that reduces latent degradation to 2.1% and achieves 100% safety monotonicity. Critically demonstrates that SAST-only gating is empirically insufficient for security assurance.
- **24.** [Evaluating C/C++ Vulnerability Detectability of Query-Based Static Application Security Testing Tools (SAST-MT)](https://ieeexplore.ieee.org/document/10400834/) ([GitHub](https://github.com/wwkenwong/SAST-MT))
    * **Description:** Designs SAST-MT, a metamorphic testing framework with 15 semantics-preserving code transformations (type, structure, and data-flow level) to systematically expose false positives and false negatives in query-based SAST tools like CodeQL. Using ~30,000 programs with known CWE/CVE, the framework detected 17 false positives and 228 false negatives in CodeQL within 100 hours, revealing that SAST tools have severe, undocumented blind spots that undermine their reliability as automated security oracles.
- **37.** [CyberSecEval 2: A Wide-Ranging Cybersecurity Evaluation Suite](https://arxiv.org/abs/2404.13161)
    * **Description:** Primary benchmark for the thesis (v2, not v1). 1,916+ prompts across multiple languages and 50+ CWEs. CWE metadata enables retrieval join with CodeGuard rules. Language-based stratification (Python + Java) for reporting. **Authors:** Bhatt et al., Meta AI, 2024.
- **38.** [LLMSecEval: A Dataset of Natural Language Prompts for Security Evaluations](https://arxiv.org/abs/2303.09384)
    * **Description:** 150 human-authored NL prompts covering MITRE Top 25 CWEs with secure reference implementations. Cross-check dataset with different prompt style from CyberSecEval v2 for robustness validation. **Authors:** Tony et al., MSR 2023.
- **40.** [SecurityEval: A Manually-Curated Security Benchmark](https://dl.acm.org/doi/abs/10.1145/3549035.3561184)
    * **Description:** 130 manually-curated Python samples across 75 CWEs designed to elicit insecure completions from coding assistants. Optional third cross-check dataset complementing CyberSecEval v2 and LLMSecEval. **Authors:** Siddiq & Santos, MSR4P&S '22 (workshop @ ESEC/FSE 2022).
